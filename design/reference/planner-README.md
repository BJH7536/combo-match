# 콤보 매칭 (Dobble형 심볼 매칭 콤보 게임)

> 📎 **기획자 원본 문서 (2026-07-26 수신) — 구버전 기준이다.**
> 이 README는 `combo-match/level@1` 스키마와 규칙 장치 3종(열쇠·폭탄·수집) 시점에 작성됐다.
> 현재 프로젝트는 **`level@2` · 장치 7종**을 쓴다 (마스터 GDD §8, ADR-001 O-2).
> 폴더 구조·경로 설명도 기획자 원본 배치 기준이라 이 저장소와 다르다.

Wood Console W2 목업 기반의 **Dobble/스팟잇형 심볼 매칭 콤보 게임**. 레벨 **설계 → 검증 → 플레이**가 하나의 레벨 스키마(`combo-match/level@1`)로 연동됩니다.

│   ├── difficulty-elements.md     # 난이도 요소 리서치 & 4계층 노브 설계 (근거 포함)
│   └── level-mechanics-brainstorm.md # 규칙 장치 조사·브레인스토밍 (도입 우선순위)
├── tools/
│   └── level-designer.html        # 레벨 디자이너: 노브 조절 → 생성/검증 → export/플레이테스트

## 연동 구조 (핵심)

디자이너와 게임은 **동일한 `combo-match/level@1` JSON 스키마**로 이어집니다.

```
🛠️ 디자이너  ──(level@1 JSON)──▶  🎮 게임
   생성/검증                          로드/플레이
```

핸드오프 채널 3가지 (모두 같은 스키마):

| 채널 | 용도 | 방법 |
|---|---|---|
| **localStorage** | 인라인/실시간 플레이테스트 | 디자이너 `▶ 플레이 테스트` → `localStorage['combo-match:playtest']` 기록 → 게임이 읽음 |
| **URL 해시** | 링크 공유 | `game/play.html#level=<base64(JSON)>` |
| **파일** | 저장/버전관리 | 디자이너 `⬇️ 레벨 JSON` → `levels/*.json` → 게임 `📂 JSON 열기` |

게임의 레벨 로드 우선순위: **URL 해시 → localStorage → 파일 → 내장 데모**.

## `combo-match/level@1` 스키마

```jsonc
{
  "schema": "combo-match/level@1",
  "seed": 1234,
  "difficulty": 29, "difficultyTier": "쉬움",
  "metrics": { "pStuck": 0, "branchFactor": 1.73, "avgMoves": 18, "solvable": true },
  "config": { "N":12,"k":2,"r":1,"cgoal":8,"wild":1,"deck":8, ... },   // 디자이너 노브 전체
  "pool": ["🍓","🍊", ...],                                            // 심볼 풀
  "active": ["🫐","⭐"],                                               // 시작 액티브 카드
  "deckStock": [["🍓","🍒"], ...],                                    // 덱 드로우로 나올 카드
  "cards": [ { "id":0,"x":..,"y":..,"layer":..,"symbols":["🐶","🫐"],"lockReq":0,"faceDown":false }, ... ],
  "coverage": [ { "id":0, "coveredBy":[3,4] }, ... ]                   // 겹침(가림) 그래프
}
```

## 코어 규칙 (게임)

- **매칭**: 보드의 free(언커버) 카드 중 액티브 카드와 심볼을 `r`개 이상 공유하면 선택 → 그 카드가 새 액티브가 됨(체이닝). **매칭 가능 카드는 표시되지 않는다** — 직접 찾는 것이 코어 재미 (힌트는 유료 아이템).
- **콤보**: 연속 매칭 시 증가, 점수 `10 × 콤보`. `cgoal` 배수마다 보너스. 덱 드로우 시 리셋.
- **덱**: 막혔을 때 드로우(콤보 리셋).
- **장애물**(`lockReq`): 콤보 연속 `≥lockReq`일 때만 제거 가능. **뒤집힌 카드**(`faceDown`): 언커버되면 공개.
- **승리**: 전체 제거. **패배**: 유효 매칭·덱·와일드 모두 소진.

## 규칙 장치 (F계층 · level@2)

디자이너 **F·규칙 장치** 그룹에서 조절, 시뮬 봇이 모두 준수하므로 대량 평가에 실측 반영된다.

| 장치 | 노브 | 규칙 | 생성 불변식 |
|---|---|---|---|
| 🔑 **열쇠-자물쇠** | 쌍 0~8 | 자물쇠 카드는 지정 열쇠 카드(🗝)를 먼저 제거해야 선택 가능. 와일드로 우회 불가(집게는 가능) | 해답 순서상 앞선 카드만 열쇠 → 항상 DAG, 데드락 없음 |
| 💣 **폭탄** | 0~4 | 표시된 수(手) 안에 제거 못하면 즉시 실패. 모든 행동(매칭·드로우·집게)마다 카운터 감소 | 카운터 = 최단 제거거리+6, 뒤집힌 카드엔 금지 |
| 🎯 **수집 목표** | 목표 유형 = collect | 지정 심볼 N개 수집 시 **조기 승리**. 보드를 다 비워도 미달이면 실패 | 최다 심볼의 75%를 목표로 자동 산정 |

그리디 봇은 폭탄 해체를 최우선(카운터 낮은 순)으로 플레이한다. 배지: 🔑n(남은 열쇠 수) · 🗝(열쇠) · 💣n(남은 수, 3 이하 빨강).

조사·브레인스토밍 근거와 2차 도입 후보(구역 쿼터·종이+조각 등)는 `design/level-mechanics-brainstorm.md` 참고.

## 경제 구조 (골드 & 아이템)

### 골드 획득 — 난이도·레벨 연동 (디자이너 E계층에서 산출)
```
기본골드   = 15 + 3×레벨번호              # 레벨 진행에 따라 선형 증가
점수환율   = 0.01 × (1 + 난이도/40)        # 난이도가 높을수록 점수당 골드↑
승리 골드  = 기본골드 + 점수×환율
패배 골드  = 승리 골드 × 0.25              # 위로보상
```
레벨 5·난이도 40이면 승리 ≈ 🪙82, 레벨 40이면 ≈ 🪙187 — **진행할수록 획득량이 점진 증가**한다. 지갑은 `localStorage['combo-match:gold']`에 영속(신규 200골드 지급).

### 아이템 상점 (판 안에서 골드로 구매, 가격 고정 = 수입 성장이 곧 파워 진행)
| 아이템 | 가격 | 효과 |
|---|---|---|
| 🔍 **힌트** | 120 | 매칭 가능한 카드 1장을 2.5초 비춤 — 상시 초록 표시를 제거한 대신의 유료 대체재 |
| 🧲 **집게** | 350 | **덮인 카드 포함** 아무 카드나 집어 제거 (콤보·액티브 유지). 재클릭 시 취소·환불 |
| 🌟 **와일드** | 500 | 아무 free 카드나 매칭 처리 (레벨 시작 보유분 소진 후 구매 가능) |

### 디자이너 연동
- **E·경제 그룹**: 레벨 번호(1~200) 슬라이더 → 기본골드·점수환율 실시간 미리보기
- **대량 평가**와 결합: 실측 평균 점수(승/패)로 **골드/판 기대치·클리어까지 기대 골드**를 자동 산출 — 레벨 번호를 바꾸면 재생성 없이 골드 기대치만 재계산
- export JSON의 `economy` 블록으로 게임에 전달 (게임은 없으면 기본값 사용)

## 난이도 설계

`design/difficulty-elements.md` 참고 — Dobble 수학, Disney Solitaire/Domino Dream, 시각탐색 인지과학 근거로 난이도를 **A지각·B구조·C자원·D압박** 4계층 노브로 환산. 디자이너가 정적 난이도 점수 + 실측 지표(분기계수 B, 막힘확률 P)를 자동 산출합니다.

## 자동 설계 & 대량 평가 프레임워크 (디자이너 v2)

### ⚡ 자동 설계: 난이도 스케일 → 레벨 패턴
목표 난이도(5~95) 슬라이더를 조정하면:

1. **아키타입 4종**(피라미드 표준형 / 스택 겹침형 / 격자 지각집중형 / 장애물 압박형) × 지터로 후보 8개 생성
2. 각 후보를 300회 봇 시뮬레이션으로 빠르게 검증
3. `종합 난이도 = 0.5×정적점수 + 0.5×실측점수(막힘확률·분기계수)`가 목표에 가장 가까운 레벨 자동 선택
4. 후보 버튼 클릭으로 **같은 난이도의 다른 패턴** 교체, `🔀 다른 패턴`으로 전체 재추첨

### 직접 조정 (자동 → 수동 연속 워크플로우)
- 자동 설계 결과가 수동 노브에 그대로 반영 → 이어서 조정하면 **수동 모드** 전환
- 보드의 **카드를 클릭**하면 심볼(풀에서 토글)·잠금(콤보 조건)·뒤집힘을 직접 편집 → 적용 시 자동 재검증(300회), 기존 대량 평가는 무효화
- 모드 배지: `⚡ 자동` / `🎛 수동` / `✏️ 편집됨`

### 🧪 대량 평가: N회(기본 10,000) 플레이 실측
Web Worker에서 봇이 레벨을 대량 플레이(랜덤=초보 / 그리디=합리적 / 혼합 50:50):

| 산출 지표 | 의미 |
|---|---|
| **실측 종합 난이도** | 정적 점수 + 실측(클리어율·분기)의 결합, 0~100 + 등급 |
| **클리어율 / 예상 시행횟수** | `시행횟수 = 1/클리어율` — 평균 몇 판 만에 깨는지 |
| **사용 아이템 수** | 판당 평균 덱 드로우 + 와일드카드 사용량 |
| 평균 이동/최대콤보, 분기 B | 플레이 텍스처 지표 |
| 정책별 클리어율 | 초보(랜덤) vs 숙련(그리디) 격차 = 실력 변별력 |

10,000회 ≈ 0.3~1초. 평가 결과는 export JSON의 `evaluation` 블록에, 생성 방식은 `generator`(mode/archetype/patternSeed/targetDifficulty) 블록에 기록되어 레벨의 **품질 증빙**이 함께 남습니다.
