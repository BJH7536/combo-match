# 레벨 디자인 가이드 (기획자용)

레벨은 **디자이너 툴에서 만들고 → 게임에서 바로 확인하고 → 마음에 들면 레벨 팩에 넣는다.**
셋 다 같은 스키마(`combo-match/level@2`)를 쓰므로 중간에 변환이 필요 없다.

| 용도 | 주소 |
|---|---|
| 디자이너 툴 | https://bjh7536.github.io/combo-match/designer.html |
| 게임 | https://bjh7536.github.io/combo-match/ |

---

## 1. 툴에서 만들고 바로 해보기 (가장 빠른 반복)

1. 디자이너 툴을 연다.
2. **⚡ 자동 설계**: 목표 난이도 슬라이더(5~95)를 옮기면 후보 8개를 만들어 300회씩 시뮬레이션하고
   가장 가까운 것을 고른다. `🔀 다른 패턴`으로 같은 난이도의 다른 배치를 뽑을 수 있다.
3. **🎛 직접 조정**: 노브를 건드리면 수동 모드로 바뀐다. 보드의 카드를 클릭하면 심볼·잠금·뒤집힘을
   개별 편집할 수 있고, 적용하면 자동으로 재검증한다.
4. **🧪 대량 평가**(기본 10,000회)로 클리어율·예상 시행횟수·아이템 사용량을 확인한다.
5. **▶ 플레이 테스트**를 누르면 게임이 그 레벨로 열린다.

플레이 테스트는 두 가지 방식으로 동시에 동작한다.

- **링크**: 주소에 `#level=<base64>`가 붙는다. 이 주소를 그대로 복사해 남에게 보내면 같은 레벨을 플레이한다.
- **같은 브라우저**: 툴과 게임을 두 탭에 나란히 띄워 두면, 툴에서 플레이 테스트를 누를 때마다
  **게임 탭이 자동으로 새 레벨로 갱신된다.** 노브 조절 → 바로 확인이 가능하다.

---

## 2. 레벨 팩에 정식으로 넣기

플레이 테스트로 만족스러운 레벨이 나왔다면 `⬇️ 레벨 JSON`으로 파일을 내려받아 저장소에 넣는다.

1. 파일을 `public/levels/level-13.json` 처럼 번호를 이어 저장한다.
2. `public/levels/index.json`의 `levels` 배열에 항목을 추가한다.

```jsonc
{
  "id": 13,
  "name": "레벨 이름",          // 선택 화면에 표시된다
  "file": "level-13.json",
  "difficulty": 41,             // 툴이 산출한 종합 난이도
  "tier": "보통",               // 툴의 등급 표기
  "devices": ["key", "bomb"],   // 선택 화면 아이콘용
  "cards": 20,                  // 카드 수
  "pStuck": 0.12,               // 툴의 막힘 확률
  "branch": 1.8                 // 툴의 분기계수
}
```

`devices`에 쓸 수 있는 값: `key`(🔑) `bomb`(💣) `zone`(🗺️) `collect`(🎯) `paper`(🧻) `lock`(🔒)
`facedown`(❔) `r2`(② 두 개 매칭).

3. 커밋해서 올리면 자동 배포된다.

> **검증이 자동으로 붙는다.** `npm test`의 레벨 팩 게이트가 새 레벨도 함께 검사한다 —
> 스키마가 맞는지, 봇이 실제로 클리어할 수 있는지, 엔진이 레퍼런스와 같은 결과를 내는지.
> 클리어 불가능한 레벨이 들어가면 배포 전에 실패한다.

---

## 3. 레벨 팩 전체를 한 번에 다시 뽑기

난이도 곡선 자체를 바꾸고 싶다면 `tools/generate-levels.mjs`의 `PLAN` 배열을 고치고 실행한다.

```bash
npm run levels     # public/levels/*.json 전체 재생성
npm test           # 품질 게이트 확인
```

`PLAN`의 각 줄이 레벨 하나다. `cfg`는 디자이너 툴의 노브와 이름이 같고, `maxStuck`은
허용 막힘 확률이다. 스크립트는 시드를 400개까지 훑어 **항상 클리어 가능하면서 막힘 확률이
상한 이내인** 레벨만 채택한다.

생성 로직은 디자이너 툴의 코드를 그대로 읽어 쓴다. 툴을 고치면 이 스크립트도 같이 따라간다.

---

## 4. 난이도를 정할 때

`design/difficulty-elements.md`의 4계층(A 지각 · B 구조 · C 자원 · D 압박)을 기준으로 삼는다.
**한 레벨에서 새로 올리는 계층은 하나만** 두는 것이 원칙이다.

현재 팩(1~12)이 그 예시다.

| 구간 | 무엇을 올리나 |
|---|---|
| 1~3 | 아무 장치 없이 카드 수만 늘린다 (난이도 13~17) |
| 4~6 | 열쇠 → 폭탄 → 구역을 하나씩 도입 (19~22) |
| 7~9 | 수집 목표 · 종이 · `r=2`, 유사 심볼군을 섞는다 (18~27) |
| 10~12 | 장치를 복합한다 (32~38, 막힘 8~23%) |

정적 난이도 점수보다 **막힘 확률(P)과 분기계수(B)** 가 체감을 더 잘 예측한다.
튜토리얼은 P < 2%·B 3~4, 표준은 P 5~15%·B 2~3, 하드는 P 20~35%·B 1.3~2가 권장 범위다.

레벨 1~3은 게임이 **고를 수 있는 카드를 초록으로 표시**하므로 규칙 학습용으로 쓰고,
4번부터는 표시가 사라진다는 점을 감안해 설계한다.
